## PDF 및 미완료
- 제공된 12개 합성 PDF의 주요 날짜·수량·PO·견적값을 JSON과 내용 대조. 사용자는 Studio에 같은 PDF를 썼다고 확인했다. PDF별 SHA와 서버 기록의 독립 대조는 미실시, Human Gold 승인 아님.
- config_version/prompt_version은 로컬 실행 시 UNKNOWN으로 입력했다. Studio Config/Workflow 및 Job 완료 이력을 독립 확인해야 한다.
- C001·C008의 제공된 Independent QA는 NOT_VERIFIED이며 QA Job ID가 위 정규화 Job ID와 다르다. 다른 실행에서 나온 QA와 정규화 결과를 동일 Job으로 간주하지 않는다. 담당자가 실제 노드 입력과 실행 이력을 확인해야 한다.
- C017 화면에는 evidence가 보이나 이번 재분석 JSON에는 evidence가 없다. 화면과 파일의 Job/Step 일치 여부를 확인한다.
- 정상 계산에서 evidence_verified_against_pdf=false이며 이는 자동 검증이 수행되지 않았다는 뜻이다.
- 각 정규화 배열은 제공된 Native JSON의 documents와 JSON 구조·값 기준 일치. 사용자가 전달한 실행 로그에서 provenance와 analysis를 확인했으나 원본 결과 파일의 바이트를 직접 확보하여 해시한 것은 아니다.

## 파일 설명과 재현
- `native_text_copies/`: 제공 JSON의 읽힌 텍스트 사본. 라이브러리 텍스트 읽기를 통해 작성했으므로 **원본 바이트 또는 위 SHA와 일치한다고 가정하지 않는다.** 원본 보존은 사용자 로컬 studio_original.json을 사용한다.
- `normalized_text_copies/`: 사용자 제공 normalized_documents의 내용 사본. 내용 비교용이다.
- `execution_output.txt`: 사용자가 PowerShell에서 출력해 전달한 로그. 개인 로컬 경로는 자리표시자로 바꿈.
- V6 CLI는 `scripts/analyze_studio_export.py`, 사례 기준 입력은 `data/cases/SYN-C###/trusted_base_case.json`. 입력 export, base, output, run-id, config-version, prompt-version을 명시하며 새로운 output 디렉터리를 사용한다. 본 실행은 네이티브 Job ID를 입력 JSON에서 읽어 run-id로 제공한 로컬 REPLAY다.

## 인계 요약
팀원 2 Python Safety V6·정규화 계약 검증 자료를 팀장 및 웹 담당자가 확인할 수 있도록 정리. 코드 신규 개발 없음. 우선 남은 실제 실행 증거와 QA를 확인하고 C6는 필수 E2E/웹 안정화 이후 별도 결정한다. 실제 결함 재현 전에는 임의 수정하지 않는다.
